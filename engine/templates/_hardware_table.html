Each row below is one published record, not one device. Two kinds of record sit here. Lifecycle rows come from {{ hardware_source_name }}'s family tables or from Opengear's end-of-life product list; Opengear groups several part numbers and product revisions into one of those rows, so a row can cover many part numbers. Catalog records come from {{ catalog_source_name }} and are one exact vendor model string each; a model's record keeps its identity even when a notice later names it. Counts here are record counts, never a count of unique devices or SKUs.

Vendor, product line and every date are taken from the record and mapped to {% for milestone in hardware_milestone_meta %}{{ milestone.short }} {{ milestone.label|lower }}{% if not loop.last %}, {% endif %}{% endfor %}; the verifier named on each record's page says which pipeline read it. Neither source publishes a security-support deadline, so EoSS is unknown throughout, and Opengear publishes no release date, so GA is unknown on its records too; a record's terminal support deadline is its end of support.

The Catalog column is deliberately separate from support. Listed in vendor catalog means the configurator lists the model today; it is not an entitlement, a support commitment or a sale guarantee. Previously listed; absent from latest catalog means the record was captured while listed and is gone from the current catalog — removal is not an end-of-sale or end-of-support announcement. A notice tag means a published lifecycle notice names this exact model string; notices that only name a revision or part order never appear there. A catalog record with neither a date nor a matching notice shows status unknown, which claims nothing in either direction — it never reads as supported.
